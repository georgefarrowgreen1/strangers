Wholesale admins can connect a UK/GBP QuickBooks Online sandbox from Invoicing, confirm the returned company and VAT registration, browse existing customers/items/VAT codes, and review mappings against an issued Strangers invoice. The screens use the existing Admin sheets and light/dark theme across phone, iPad and desktop.

This is the connection and preview milestone: accounting writes, invoice emails, payment collection and balance synchronisation remain disabled. A real Intuit sandbox has not yet been validated; missing credentials show setup guidance and leave connection unavailable. Local issued invoice/PDF snapshots and customer payment statuses remain authoritative.

OAuth states are hashed, short-lived, single-use and bound to the initiating admin/session/version. Tokens use AES-GCM with a separate Worker secret and company/generation binding. Refresh leases and version guards prevent disconnect races and stale results. Provider destinations are fixed, redirects refused, reference responses minimal, and errors redacted. Mappings are company scoped and version checked; active sales items and VAT percentages are revalidated. Per-request reference caching keeps 150-variant invoices and shared historic VAT mappings within the request budget. Customer/staff/manager APIs cannot access integration data.

Append-only migration 15 adds connection, OAuth-state, mapping and installation tables in existing D1. JSON backups retain mappings/installation identity without credentials or active state. Setup/recovery documentation covers independent encryption keys and clearing integration credentials before raw D1 restores. No new DNS, queue binding, SDK dependency or paid service is provisioned. Intuit app credentials/consent are still required for a real sandbox connection.

Validation: npm test passes TypeScript and all 198 API/PDF tests; npm run test:e2e passes all 93 browser tests (291 total) on the frozen source. The suite covers role/identity/Origin boundaries, OAuth replay and session binding, encryption, company and VAT validation, mapping conflicts, rotating refresh tokens, disconnect races during refresh and reads, 150-variant invoices, 100 historic VAT mappings sharing one code, redacted failures and backup exclusions. Six native QuickBooks browser workflows cover phone, iPad and desktop in both themes, including colliding customer/VAT IDs. Missing-configuration screens and focused screenshots were reviewed. Worker dry build, JavaScript syntax, clean-tree and diff checks pass. The CI job allows 30 minutes for the complete sequential suites.
