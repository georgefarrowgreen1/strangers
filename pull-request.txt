An interrupted initialization request can leave the Worker caching a promise that Cloudflare will never settle after its owner request has ended. Subsequent page and API requests then fail at ensureSchema with E-0FMM57 / E-M4FG35 instead of loading.

Cache completed schema readiness per database, and cache only resolved session-signing CryptoKeys per database. Every in-flight initialization owns its I/O, a failure cannot poison later requests or clear another successful result, and the existing stored signing key remains authoritative. Keep the existing migrations, cookie format, authorization and privacy checks; no compatibility flags or secrets change.

The new abandoned-request regressions fail against the previous caches and pass with this change. They cover independent recovery, retry, late failure and per-database signing-key isolation. Eight simultaneous real Worker cold-start requests and 14 focused migration/identity/security checks also pass.

Validation: npm test (335 API/PDF/unit tests plus type checking), npm run test:e2e (183 browser tests), 14 focused migration/identity/security checks, eight simultaneous real Worker cold starts, Worker dry build and diff checks pass. Three regressions fail against the former request-owned caches; all four new lifetime/cache tests pass with the fix.
